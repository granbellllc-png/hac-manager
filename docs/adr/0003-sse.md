# 0003. SSE for durable event streaming

## Context and problem statement

Jobs continue when a browser closes or a user changes devices. Logs, queue events and prompts must resume after reconnect. FEATURES.md D-27, D-30 and D-33 replace WebSockets for these streams.

## Considered options

- Polling.
- WebSockets for all real-time traffic.
- Server-Sent Events with REST writes.

## Decision outcome

Use SSE for server-to-client job logs, queue events and prompts. Persist each log line separately in job_log_lines, assign stable event IDs and resume from Last-Event-ID. Answer prompts and invoke actions through authenticated REST endpoints. Reserve WebSockets for the later interactive web console.

## Consequences

HTTP streaming and browser reconnection are straightforward. Delivery still needs durable replay, authorization and disconnect cleanup. Reverse proxies must avoid buffering and enforce suitable timeouts. A live stream alone is never the log source of truth. Secret redaction applies before persistence and emission.

## Validation

Test reconnect replay, event ordering, authorization, restarts and secret leaks. A user switching devices must see previous log lines and pending prompts without rerunning the job.
